# 武器闪电链移植可行性

检查日期：2026-11-13。

源工程：`E:/Java/IceAndFire-CE`，当前 `master` 的 `7ae3fcc34593c2abe844908504b540799cf690ea`；同时核对 `1.20.1` 分支的 `52f07c64951eea4faf609bc3ec77136e5a6a6e54`。

目标工程：`E:/Java/IAF-Patcher`，`stonecutter` 分支的 `ea3caba800a3961b22fb63e16516005ff5251c52`，模组版本 `2.0-beta.1`。

## 结论

可以移植，四个目标版本都有可复用的同源闪电几何生成器和渲染器，不需要新增前置模组，也不需要复制 CE 的整套渲染实现。相比单纯的 bug 补丁，这项功能还需要客户端渲染事件和一个服务端到客户端的端点同步包；属于规模可控的功能移植。

本轮仅完成源码和依赖 JAR 的可行性分析，没有修改功能代码，没有编译新实现或进行客户端效果验证。

## CE 实际提供的行为

当前 CE 的 `item/ability/LightningMultihitAbility.java` 被龙霆钢剑、斧、镐、锹和锄共用：

- 命中 Mob 后，服务端在攻击者周围搜索其他存活、可见的 Mob；首个被击中目标算入总目标数。
- 每个次级目标受到武器攻击属性乘伤害系数的额外伤害。
- 把首个目标和各个次级目标包围盒中心的坐标配对，发给攻击者 64 格内的玩家。
- 客户端生成紫色分叉电弧，使用 `ELECTRICITY`、4 段、粗细 `0.05`、寿命 10 tick、淡入淡出比例 `0.1`、`NO_DELAY`。

默认搜索半径为 10，目标数上限为 10，伤害系数为 0.5。当前实现实际形成的是由首个目标向其他目标放电的多条连接，不是逐个跳向越来越远目标的链式搜索；复刻时无需引入新的 BFS。

这套效果用于龙霆钢系列。电龙血龙骨剑走 `LightningDragonBloodToolAbility` / `SummonLightningAbility`，仍然召唤原版天雷。

需要区分两个移植范围：

1. **视觉接入**：提供任意起终点的短时电弧渲染与同步；本身不添加范围伤害。要让武器出现多目标连接，仍需定义这些端点如何选择，否则旧版武器只会召唤天雷。
2. **完整龙霆钢能力**：同时移植目标选择、连锁伤害和画面，替换旧版龙霆钢的召雷分支。这会改变战斗行为；不能把它当成纯客户端换皮。

## 目标版本逐项核对

从 Patcher 配置的实际 mapped 依赖 JAR 提取相关类，再用本地 Vineflower 反编译核对，未修改依赖 JAR 或映射缓存。

| Minecraft / Forge | IAF CurseForge 文件 ID | 闪电工具 | 武器入口 | 可用渲染事件 |
| --- | --- | --- | --- | --- |
| 1.16.5 / 36.2.42 | 4614457 | `client.particle.LightningBoltData`、`LightningRender` | 五个 `ItemMod*` 类各自实现召雷分支 | `RenderWorldLastEvent` |
| 1.18.2 / 40.3.10 | 5037775 | 同上 | 五类调用 `DragonSteelOverrides.hurtEnemy` 默认方法 | `RenderLevelStageEvent` |
| 1.19.2 / 43.4.4 | 5037952 | 同上 | 同 1.18.2 | 同上 |
| 1.20.1 / 47.3.3 | 5633453 | 同上 | 同 1.18.2 | 同上 |

四版均确认存在 `LightningBoltData` 的 `ELECTRICITY`、`size`、`lifespan`、`fade`、`spawn`、`NO_DELAY`，以及 `LightningRender.update` / `render`。紫色、分叉率和噪声参数也与 CE 对应实现相同。1.16.5 的向量、矩阵和缓冲类型不同，但直接调用它自身依赖提供的实现即可适配。

Forge 事件签名以本机各版 `forge-<mc>-<forge>-sources.jar` 为依据；1.16.5 用 `getMatrixStack()` / `getPartialTicks()`，后三版用 `getPoseStack()` / `getPartialTick()`。后三版均存在 `AFTER_PARTICLES` 阶段。

## 建议的最小接入方案

- **复用原冰火渲染器**：保留 CE 的颜色、分叉和寿命参数；不移植 NeoForge 26 的 `SubmitNodeCollector`，也不引入 Architectury / Jupiter。
- **客户端事件绘制**：在已核对的 Forge 世界渲染事件中平移摄像机坐标并绘制；明确提交闪电对应的缓冲，避免事件晚于原版缓冲提交时导致画面不出现。无需新增世界渲染 Mixin。
- **端点同步**：新增小型 S2C 包，只同步同维度的一组起终点；客户端主线程接收并提交渲染。
- **局部武器补丁**：完整移植时仅接管龙霆钢电属性的召雷分支，继续执行原物品耐久逻辑。1.16.5 可用多目标 Mixin 覆盖五个 `ItemMod*`，现代版本可评估在公共默认方法集中接入。最终 Mixin 数量及默认接口注入可行性需由实际编译和 Mixin 应用测试确认。
- **配置**：完整能力建议提供总开关、搜索范围、总目标数和伤害系数；客户端另设显示开关。关闭完整能力时恢复旧版行为，客户端关闭画面不影响服务器判定。

## 实现时必须处理的具体问题

1. 旧版 `LightningRender` 构造时缓存 `Minecraft.getInstance()`，应在客户端已初始化且有世界时延迟创建，避免从公共初始化路径提前加载客户端类。
2. 切换世界/维度及退出服务器时清理待绘制端点并重建渲染器。其内部过期逻辑使用世界时间，不能把旧世界的闪电缓存带到新世界。
3. 一次目标查询即可复刻当前 CE 的目标选择；按目标上限停止选择，限制端点队列，不能为每一条连接反复搜索实体。
4. 移植完整能力时需要替换原龙霆钢召雷，避免同时出现旧天雷和新范围伤害；不能在物品方法 HEAD 直接取消整个方法而丢失耐久消耗。
5. CE 当前的选择条件没有额外排除同阵营和宠物。若完整照搬，会保留这一行为；是否加入友军排除是单独的玩法决定。
6. 纯视觉接入无需改变伤害。完整能力则需要明确保留的击退、冷却和配置关闭行为，并测试五种物品，而非只测剑。

## 后续验证方法

- 四版构建和 Mixin 应用测试；专服启动确认没有加载客户端渲染类。
- 客户端用一把龙霆钢剑攻击单个生物及一组生物，核对连接数量、紫色分叉、淡出、遮挡和摄像机移动；再测斧、镐、锹、锄的耐久。
- 两客户端联机确认旁观者看到同一批连接，跨维度不串图，切维度/重连不残留旧闪电。
- 若移植完整能力，验证搜索半径、目标数（包括初始目标）、伤害系数、开关恢复旧行为，以及不额外召唤旧天雷。
