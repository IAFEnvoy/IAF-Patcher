# CE 小功能迁移候选（2026-11-12）

对照 CE 当前 `master`（`7ae3fcc3`，Minecraft 26.1.2）、CE `1.20.1` 分支，以及 Patcher 四个已配置的原版依赖，筛选少量 Mixin 或纯数据文件即可实现的增强。本轮仅分析并新增本报告，没有修改功能代码、版本号或更新日志。

目标依赖和哈希继续使用 [既有证据清单](ce-backport-evidence-2026-11-12.json)。额外反编译的配置、实体、配方和客户端事件保存在本机 `build/small-features-review-2026-11-12/<版本>/sources/`；既有实体、AI 和服务端事件证据仍在 `build/ce-migration-review-2026-11-12/`。

下表的 Mixin 数是静态实现估计，不代表已经编译或进游戏验证。若需要新开关，可以共用一份 Forge 配置；Patcher 当前没有这套功能配置，不应把 CE 的 Jupiter 配置框架整体搬过来。

## 建议候选

| 顺序 | 功能 | 玩家收益 | 目标版本 | 预计实现量 |
| --- | --- | --- | --- | --- |
| 1 | 鳞片 + 玻璃瓶在对应锻炉中制取龙血 | 增加获取龙血的途径，减少对龙尸取血的依赖 | 四版 | 0 Mixin；3 个配方及必要的标签适配 |
| 2 | 普通龙食解除病变龙食造成的停止生长 | 给停止生长提供可逆操作 | 四版 | 1 个龙实体 Mixin，局部注入 |
| 3 | 海马可选免疫气泡柱 | 骑海马经过灵魂沙、岩浆块时不被气泡柱拉动 | 四版，方法签名须逐版适配 | 1 个海马 Mixin，覆盖两种气泡柱回调 |
| 4 | 使用刷子从成年驯龙采集鳞片 | 不杀龙也能补充鳞片，与龙血配方搭配更有价值 | 优先仅 1.20.1 | 1 个龙实体 Mixin，但含交互、保存、读取、次数恢复等多个注入点 |
| 5 | 龙不再被船自动载走，采用简化方案 | 避免龙碰到船后卡在船里 | 四版静态可行 | 预计 1 个龙实体 Mixin，处理上船判定 |
| 6 | 为旧版补齐部分喂食 / 繁殖 / 驯服标签 | 整合包可用数据包自定义食物 | 主要是 1.16.5、1.18.2 | 按单一生物分批，通常 1～2 个 Mixin 加标签；不要一次覆盖全部生物 |

### 1. 鳞片换龙血：最省事的一项

CE 当前的三个配方位于 `src/main/resources/data/iceandfire/recipe/dragonforge/*_dragon_blood.json`。同属性鳞片和玻璃瓶在对应锻炉中生成一瓶龙血，配方时间为 750 tick。该功能最初来自 `b027ce9f`，不属于 CE 1.20.1 分支已有内容。

核对四版原版 JAR，均未包含这些龙血配方。四版 `DragonForgeRecipe.matches` 都按两个 Ingredient 和龙属性匹配，锻炉第二槽的 `canPlaceItem` / `isValidBlood` 按配方判断，并未写死只能放龙血，因此可以直接利用现有配方系统。1.20.1 菜单的两个输入槽也是普通 Slot。

不能直接复制 26.1.2 JSON：原版四版使用 `recipes/`、`dragon_type`、`cook_time` 和 `result.item`，输入也是 Ingredient 对象。鳞片标签亦有差异：

| 版本 | 火龙鳞片标签示例 |
| --- | --- |
| 1.16.5、1.18.2 | `forge:scales/fire_dragon` |
| 1.19.2、1.20.1 | `iceandfire:scales/dragon/fire` |

建议只新增配方及必要标签，不修改锻炉状态机。本功能仍受原版锻炉既有缺陷影响，不能据此宣称锻炉问题已经修复。验证应覆盖三种炉、手动放瓶、漏斗放瓶、原有龙钢配方以及 `/reload`。

### 2. 普通龙食恢复生长：最小的行为增强

CE 当前 `DragonBaseEntity.mobInteract` 在普通龙食的生长分支内先调用 `setAgingDisabled(false)`，再调用 `growDragon(1)`。核对原版四版，对应普通龙食分支只有 `growDragon(1)`；`growDragon` 在停止生长时直接跳过增长，也没有其他 `setAgingDisabled(false)` 恢复路径。

可在普通龙食分支调用 `growDragon` 前局部恢复标记，保留原来的主人判断、消耗、回血和粒子。不要全局改 `growDragon`，否则会影响生成和其他年龄调整调用。

这是玩法增强：原本停止生长的龙也可能被玩家喂普通龙食恢复血量，迁移后会同时恢复生长，适合提供开关。验证重点是普通 / 病变龙食切换、非主人操作、重进世界后的标记和年龄变化。

### 3. 海马气泡柱免疫：一个独立开关

CE 当前 `HippocampusEntity.onInsideBubbleColumn` 和 `onAboveBubbleColumn` 根据 `hippocampus.bubbleColumnImmunity` 决定是否调用父类，默认关闭。四版原版海马都没有这两个覆盖。

可以只在海马类上补覆盖，关闭时调用正常父类逻辑，开启时跳过气泡柱影响。不要直接在所有生物的气泡柱处理上增加特判。26.1.2 的柱顶回调带位置参数，旧版方法签名需要查对应 Minecraft 源码，不能照抄。验证灵魂沙上升、岩浆块下拉、柱顶、骑乘和开关关闭后的原行为。

### 4. 刷鳞片：功能小，但需要完整的次数记录

CE 当前限制只有主人能刷、龙达到第三阶段、未超过次数上限；用 `BrushedTime` 保存次数，并在喂食相关分支恢复额度。原版 1.20.1 已有刷子和对应鳞片物品，适合做单版本增强。

旧三版没有原版刷子。若要给它们增加物品、配方、贴图和交互，就超出本轮的简单移植范围，建议暂不覆盖。

应完整实现服务端掉落 / 扣次数、NBT 保存读取和额度恢复，不能只注入一个右键掉落分支。还要测试龙角收放、区块卸载和重启，防止额度被重置成无限采集。它与第 1 项组合后才构成稳定的不杀龙取血路线。

### 5. 船：建议迁移目的，简化实现

CE 的 `destroyBoats` 来自 `b95e0be2`，包含处理已骑上的船，以及查询附近船并破坏的逻辑。完整复制会增加活龙的周期性实体查询；当前已骑乘分支还直接 `remove(KILLED)`，不宜据此承诺所有路径都有正常掉落。

遵循本轮“尽量简单”的目标，可以先只阻止龙被船自动载走，保留幼龙骑主人等正常关系。这是 CE 功能的简化变体，不包含碰撞就拆掉附近船的效果。已在船里的旧实体如何退出需要单独处理，不能说只拦截上船即可修复已有存档中的全部卡船情况。

### 6. 喂食标签：只补旧版缺项

CE 使用 `breed_*`、`heal_*`、`tame_*`、`tempt_*` 标签。核对原版实际 JAR 和实体调用后：

- 1.19.2、1.20.1 已有大部分同名标签及读取逻辑，包括羽蛇、海马、鹰马、鸡蛇和精灵相关食物；无需重复移植。
- 1.16.5、1.18.2 的羽蛇繁殖 / 治疗仍写死曲奇 / 可可豆，鹰马繁殖写死兔肉煲等，值得按生物逐组补齐。

例如只做羽蛇时，要同时处理右键喂食、`isFood` 和拾取食物 Goal 的判定，不能只新增 JSON。默认标签应保持旧物品集合，玩家用数据包按需扩展。

## 暂不优先的增强

- Jade 的龙阶段、年龄、性别和蛋孵化时间显示：CE 有现成 provider，原版四版 JAR 没有对应 Jade/Waila 集成。基本显示可做到 0 Mixin，但属于可选兼容，需要处理不同版本 API、未安装时隔离加载；冰蛋的年龄数据还要核对服务端同步。若只想做无需兼容模块的小功能，优先级低于前三项。
- 通过 `summon_ghost_sword` 标签赋予其他武器剑气：CE 已有，但原版仍把它写死在 `ServerEvents.onLeftClick`。已有挥手消息通道涉及客户端触发、冷却和服务端线程，不能仅换一个物品条件便算完整迁移，暂不放入最简单一批。
- 飞行重制、体力 / HUD、新龙钢装备、可配置龙种和结构生成重写：涉及网络、渲染、注册或世界生成，不符合本轮范围。

以下开关原版四版已经存在，也不作为新增收益：`dragonAuto3rdPerson`、`dragonFluteDistance`、`sirenShader`、`doDragonsSleep`、`dragonHungerTickRate`。Patcher 已有的精灵偷窃黑名单和猪灵喜爱物品标签也不重复计算。

## 推荐顺序与验证边界

建议先实施 **龙血配方 → 普通龙食恢复生长 → 海马气泡柱开关**。希望有更明显的新玩法时，再做 **1.20.1 刷鳞片**；船与旧版食物标签独立安排。

本轮完成了四版依赖资源检查、相关类反编译与 CE 源码对照，没有编译或运行这些尚未实现的功能。上一轮简单补丁的回归结果不能当作这些新候选的验证结果；1.16.5 的开发运行环境仍有上一轮记录的上游映射 JAR 重复方法阻断。
